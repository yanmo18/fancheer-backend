# 数据库指南

> Fancheer Backend 数据库配置、Schema 说明与日常操作。

## 技术栈

| 组件 | 说明 |
|------|------|
| 数据库 | MySQL / MariaDB 10+ |
| ORM | Prisma 7.x |
| 驱动适配器 | `@prisma/adapter-mariadb`（Prisma 7 必需） |
| 配置文件 | `prisma/schema.prisma` + `prisma.config.ts` |
| 客户端输出 | `generated/prisma/`（gitignore，需 `pnpm prisma:gen`） |

## Prisma 7 适配器

Prisma 7 不再内置数据库驱动，项目通过 MariaDB 适配器连接 MySQL：

```typescript
// src/lib/prisma.ts
import { PrismaMariaDb } from '@prisma/adapter-mariadb'
import { PrismaClient } from '../../generated/prisma/client'

const dbUrl = new URL(process.env.DATABASE_URL!)
const adapter = new PrismaMariaDb({
  host: dbUrl.hostname,
  port: parseInt(dbUrl.port) || 3306,
  user: dbUrl.username,
  password: dbUrl.password,
  database: dbUrl.pathname.slice(1),
})
export const prisma = new PrismaClient({ adapter })
```

**注意**：全项目只使用这一个 `prisma` 实例，不要在 service 外重复创建。

## 环境变量

```env
DATABASE_URL="mysql://user:password@localhost:3306/fancheer"
```

格式：`mysql://用户名:密码@主机:端口/数据库名`

### ID 类型

所有主键使用 `BigInt @db.UnsignedBigInt`。API 层通过 `BigInt.prototype.toJSON` 全局序列化为字符串，解析时使用 `parseId()`（`src/utils/id.ts`）。

## 迁移工作流

### 首次初始化

```bash
pnpm prisma:gen          # 生成 Prisma Client
pnpm prisma:migrate      # 应用迁移（仓库已含 init 迁移）
pnpm seed:assets         # 可选：同步 Docker 用素材
pnpm seed:uploads        # 生成 uploads 静态文件
pnpm seed                # 导入测试数据
```

### 日常 Schema 变更

1. 编辑 `prisma/schema.prisma`
2. 运行迁移：
   ```bash
   pnpm prisma:migrate
   ```
   输入描述性迁移名，如 `add_user_bio_field`
3. 更新对应的 service 查询和业务逻辑
4. 如需测试数据，同步更新 `seed.ts`

### 其他命令

| 场景 | 命令 | 说明 |
|------|------|------|
| 快速原型同步 | `pnpm exec prisma db push` | 不生成迁移文件，直接同步 schema（Docker 启动时也用此方式） |
| 从现有 DB 拉取 | `pnpm exec prisma db pull` | 反向生成 schema |
| 可视化浏览 | `pnpm prisma:studio` | 浏览器 GUI 查看/编辑数据 |
| 重新生成 Client | `pnpm prisma:gen` | schema 变更后必须执行 |

## Prisma Studio 使用

1. 确保 `.env` 中 `DATABASE_URL` 配置正确
2. 运行：
   ```bash
   pnpm prisma:studio
   ```
3. 浏览器自动打开（默认 `http://localhost:5555`）
4. 左侧选择表名，可查看、新增、编辑、删除记录

**提示**：Studio 直接操作数据库，修改会立即生效，生产环境慎用。

## MySQL vs Redis 职责

| 存储 | 用途 | 查看方式 |
|------|------|----------|
| **MySQL** | 持久化业务数据（用户、消息、内容等） | Prisma Studio / MySQL 客户端 |
| **Redis** | 临时缓存（验证码、JWT 黑名单、限流） | Redis CLI / RedisInsight |

Redis **不是**数据库替代品，不能用来查看 MySQL 数据表。

## 常见问题

### `Cannot find module '../../generated/prisma/client'`

运行 `pnpm prisma:gen` 生成客户端。

### 迁移冲突

开发环境可重置：
```bash
pnpm exec prisma migrate reset   # 危险：清空数据库并重新迁移+seed
```

### BigInt 相关错误

- API 返回：已在 `app.ts` 全局处理
- 代码内部：使用 `parseId()` 解析路径参数，不要用 `Number(id)`

### 启动报 `pool timeout` / `RSA public key is not available`

MySQL 8 本地连接常见。处理方式（任选其一）：

1. **代码已默认处理**：连接 `localhost` / `127.0.0.1` 时自动开启 `allowPublicKeyRetrieval`
2. **或在 `.env` 的 `DATABASE_URL` 末尾加**：`?allowPublicKeyRetrieval=true`
3. 确认 MySQL/MariaDB 服务已启动，且库名、用户名、密码正确

### 时区问题

打卡模块使用 `Asia/Shanghai` 时区（见 `src/config/constants.ts` 的 `TIMEZONE`）。
