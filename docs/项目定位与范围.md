# 项目定位与范围

> Fancheer Backend 的产品边界说明。单人开发、自行上线时，明确「做什么」和「不做什么」。

## 项目定位

**Fancheer 是一个博主个人展示站的后端 API** —— 为**单一博主/创作者**提供个人主页、作品展示、轻量社区互动和内容管理能力。

不是直播平台，不是多主播社区，不是电商或打赏系统。

### 一句话描述

> 我的个人网站：展示我自己 + 访客注册后可以留言互动 + 我自己管理内容和访客。

## 保留的功能（当前已实现）

| 模块 | 说明 | 产品语义 |
|------|------|----------|
| 首页展示 | Banner、博主资料、获奖/荣誉、音乐、活动、图集、关系图谱 | 个人作品集 |
| 用户中心 | 注册登录、昵称头像、每日打卡 | 访客轻量参与 |
| 留言互动 | 公开留言、私密留言、点赞、举报、博主回复 | 社区互动（非直播弹幕） |
| 管理后台 | 用户管理、内容 CRUD、举报处理、敏感词、操作日志 | 站主自用后台 |
| 文件上传 | 图片/音频上传 | 内容维护 |

## 明确不开发的功能

以下功能**不在项目范围内**，后续也不会添加，以降低自行上线时的合规与封禁风险：

| 不开发 | 原因 |
|--------|------|
| 多主播 / 多博主平台 | 本项目仅服务**单一博主**，不做平台型产品 |
| 直播推流 / 实时音视频 | 涉及直播资质与内容监管，不做 |
| 打赏 / 付费订阅 / 虚拟礼物 | 涉及支付与金融合规，不做 |
| 电商 / 购物车 / 订单 | 涉及电商资质，不做 |
| 抽奖 / 赌博 / 付费投票 | 敏感合规风险，不做 |

若未来有类似需求，应使用**独立合规产品**（如已有支付牌照的平台），而不是在本项目中扩展。

## 角色与代码对照

代码中的角色名是历史命名，**产品语义**如下：

| 代码角色 | 产品称呼 | 是谁 |
|----------|----------|------|
| `streamer` | **博主 / 站主** | 网站拥有者（你自己），最高权限 |
| `admin` | **协管员** | 博主信任的助手，可管内容，不可看全部私密留言 |
| `fan` | **注册访客** | 注册后可以留言、打卡的普通用户 |
| 未登录 | **游客** | 只能浏览公开展示内容 |

> 代码里仍使用 `streamer`、`streamer_info`、`/api/streamer-info` 等命名，**无需改名**，文档和前端文案统一称「博主资料」即可。

## 上线建议（自行部署时）

1. **内容定位**：个人展示 + 作品分享 + 轻量留言，避免「直播」「打赏」「商城」等敏感词出现在首页和 SEO
2. **敏感词**：保持后台敏感词管理开启，定期更新
3. **举报机制**：保留举报与消息删除能力，便于处理违规留言
4. **备案与域名**：国内上线按当地要求完成 ICP 备案等手续
5. **Seed 数据**：上线前替换为真实个人内容，不要使用「虚拟主播」「直播」等示例文案
